## 2. Mathematical Model & Slot Double-Booking Prevention

### 2.1 Half-Open Interval Definition

Time slots are modeled as half-open intervals $[s, e)$, where:
- $s = \text{start\_at}$ (inclusive)
- $e = \text{end\_at}$ (exclusive)

Two time slots $A = [s_A, e_A)$ and $B = [s_B, e_B)$ on the same physical charger $c$ overlap if and only if:
$$s_A < e_B \quad \land \quad e_A > s_B$$

#### Adjacent Booking Behavior (Valid)
Consider adjacent bookings on charger $c$:
- Booking 1: $[10:00, 11:00)$
- Booking 2: $[11:00, 12:00)$

Evaluating the overlap condition:
$$s_1 < e_2 \implies 10:00 < 12:00 \quad (\text{True})$$
$$e_1 > s_2 \implies 11:00 > 11:00 \quad (\text{False})$$

Because $e_1 > s_2$ evaluates to **False**, the intersection $[10:00, 11:00) \cap [11:00, 12:00) = \emptyset$. Both bookings are accepted without conflict.

#### Overlapping Booking Behavior (Conflict)
Consider overlapping bookings on charger $c$:
- Booking 1: $[10:00, 11:00)$
- Booking 3: $[10:30, 11:30)$

Evaluating the overlap condition:
$$s_1 < e_3 \implies 10:00 < 11:30 \quad (\text{True})$$
$$e_1 > s_3 \implies 11:00 > 10:30 \quad (\text{True})$$

Both conditions are **True**, yielding intersection $[10:30, 11:00) \neq \emptyset$. The engine immediately rejects Booking 3 with `HTTP 409 Conflict`.

## 3. PostgreSQL 18 Exclusion Constraint Architecture

The production migration blueprint in `database/schema/proposed_reservation_exclusion_constraint.sql` enforces zero double-booking at the PostgreSQL engine level:

```sql
-- Step 1: Enable extension for GiST index support on scalar types (bigint)
CREATE EXTENSION IF NOT EXISTS btree_gist;

-- Step 2: Enforce mathematical time-range exclusivity on active bookings
ALTER TABLE reservations
ADD CONSTRAINT no_overlapping_active_reservations
EXCLUDE USING gist (
    charger_id WITH =,
    tstzrange(start_at, end_at, '[)') WITH &&
)
WHERE (status IN ('PENDING', 'CONFIRMED'));
```

### Key Technical Aspects:
1. **Range Operator `tstzrange`:** The PostgreSQL `reservations` table uses `timestamp with time zone` (`start_at` and `end_at`). The range type must be `tstzrange(..., '[)')` to honor half-open boundaries.
2. **Partial Index Filter (`WHERE status IN ('PENDING', 'CONFIRMED')`):** Excludes inactive records (`COMPLETED`, `CANCELLED`, `NO_SHOW`). When a driver cancels, their record remains in history for audit purposes, but the slot is instantly freed at the index level.
3. **Precondition Verification:** Inspected all 7 existing reservation rows in PostgreSQL 18. Verified zero active overlaps:
   - Row 1: `2026-11-13 10:00:00+05:30` to `2026-11-13 11:00:00+05:30` (Charger 1)
   - Row 2: `2026-11-13 11:30:00+05:30` to `2026-11-13 12:30:00+05:30` (Charger 1)
   - Row 3: `2026-11-13 09:00:00+05:30` to `2026-11-13 10:00:00+05:30` (Charger 2)
   - Rows 4–7: Mutually disjoint across respective chargers.
